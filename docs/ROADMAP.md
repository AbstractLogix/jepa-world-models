# JEPA World Models Tutorial Roadmap

**Research snapshot**: 2026-10-15

**Scope**: Educational tutorials on JEPA representations, video prediction, actions, and planning. This is a curated research map, not a claim that one method is best on every task.

## Research themes

- **Representation objectives**: LeJEPA studies isotropic Gaussian embeddings and SIGReg; Rectified LpJEPA adds distribution matching for sparse, non-negative representations.
- **Object-centric features**: the current v2 of object-centric LeJEPA uses human ground-truth COCO instance masks in its main experiment; SAM masks and superpixels are separate ablations. Its semantic object alignment uses SIGReg, with a second instance-separation loss and copy-paste augmentation.
- **Video features**: V-JEPA 2 learns video representations and adds an action-conditioned model for planning. V-JEPA 2.1 focuses on dense and temporally consistent features.
- **Language**: VL-JEPA predicts text embeddings and uses a decoder when text output is needed.
- **Planning**: Value shaping, gradient-based planning, and physical-planning ablations study how representations and planners affect control.
- **Hierarchical planning**: H-JEPA learns action-conditioned models at multiple temporal scales and plans from abstract goals down to lower-level subgoals. Notebook 19 teaches this flow with hand-written CPU examples; it is not a learned model or a paper reproduction. Its Visual AntMaze result is a recent author-reported result, not a universal ranking of JEPA methods.
- **Limits and evaluation**: Recent work studies the range where imagined trajectories help action choice, as well as reusable evaluation systems for fair comparison.
- **Decision-useful evaluation**: Recent reviews argue that visual plausibility and one-step prediction alone do not establish planning value. Stronger evidence measures response to changed actions, closed-loop validity, policy ranking or improvement, model exploitation, and uncertainty. These are separate evidence questions, not one score.
- **Actions from video**: Latent-action work studies how to learn action spaces without action labels, including transfer limits when videos have different cameras or embodiments.
- **Sparse action-conditioned world models**: LpWM studies whether non-negative sparse codes make action-conditioned dynamics easier to model than dense representations.
- **Joint world-action models**: LeWAM work trains latent dynamics and action generation together. Two separate studies now have released code and checkpoints: the Push-T work at arXiv:2610.12818 and a RoboTwin 2.0 work at arXiv:2609.27455. Their names, tasks, data, and claims differ.
- **Control-grounded representations**: GA-WM adds inverse-dynamics and physical-state alignment losses. Hamiltonian JEPA separates perceptual and control states and uses port-Hamiltonian dynamics. These differ from the hierarchical H-JEPA lesson and LeHami's symplectic-flow study.
- **Multi-paradigm JEPA inference**: Qantara trains one latent world model for goal-conditioned planning, goal-blind action sampling, and video–inverse action recovery. The paper tests which path fits the task and its data; it does not claim real-robot transfer.
- **Structured latent dynamics**: LeHami combines action-conditioned latent predictions with Hamiltonian dynamics and reports an exactly symplectic latent flow. This structural property does not guarantee accurate rollouts or useful control.
- **Physics-parameter generalization**: Semigroup-JEPA supplies gravity to a recursively trained latent predictor and tests long-horizon prediction across a held-out gravity grid. It varies one provided scalar and does not infer physical parameters from observations.
- **Geometric observations**: Point-cloud JEPA work tests whether latent planning transfers from images to sparse 3-D observations and whether goals can be represented from target coordinates.
- **Cross-domain prediction**: JEPA-Anything proposes orthogonal predictive factors across vision, biology, clinical data, control, molecular dynamics, physical fields, and weather. Its current repository provides reusable core code and a synthetic structural example, not the paper's domain datasets or trained weights.

The papers report results for their own data, tasks, and run settings. Those results are research inputs; they are not results from this repository.

## Source notes

- **V-JEPA 2** reports video pretraining and post-training an action-conditioned model with less than 62 hours of unlabeled DROID robot video. This is the paper's reported setup, not a general data requirement.
- **V-JEPA 2.1** reports dense, temporally consistent features and results across video, perception, and robotics tasks. A tutorial must use the official checkpoint and report its own measured task.
- **LpWM** reports a planning-success advantage over dense LeWM at intermediate predictor capacities on PushT. The first local attempt verified the official source and data, then was OOM-killed before epoch 1 on CPU. No checkpoint or planner result exists; a safe resource plan is still needed. See the [attempt report](reproductions/lpwm-pusht.md).
- **VL-JEPA** predicts continuous text embeddings and invokes a decoder when text is required. Version 2 reports a 1.6B-parameter system, large-scale image/video pretraining, and classification, retrieval, and question-answering benchmarks. Notebook 11 measures a small supervised class-prompt analogue with ResNet-18 and MiniLM; it does not validate those paper findings. The 2026-10-14 source review did not confirm a first-party code or checkpoint source.
- **Object-centric LeJEPA** uses given masks rather than learning a scene partition. Its main v2 experiment uses human ground-truth COCO instance masks; SAM and superpixel masks are separate ablations. The paper reports ADE20k object-classification balanced accuracy of 0.555 for its semantic object representation and 0.426 for image-level LeJEPA, with one seed per configuration. Notebook 13 completed a reduced Oxford-IIIT Pet transfer study; its five-seed paired interval includes zero. It does not reproduce or validate the COCO result.
- **Value-guided planning** shapes embedding distances to approximate a goal-conditioned value signal on the paper's control tasks. CartPole alone is not evidence of physical planning.
- **GRASP** uses virtual states and soft dynamics constraints to optimize long action plans. A planner that only optimizes a short action sequence is not automatically a GRASP reproduction.
- **The planning-limits preprint** reports that action ranking can fail when goals lie far beyond the imagined rollout and studies feedback and subgoals. Its numerical findings apply to its evaluated tasks, not all world models.
- **The physical-planning study** evaluates JEPA world models in simulation and with robot data. The current CartPole ablation does not reproduce that evaluation.
- **Decision-making evaluation** distinguishes evidence about generated or predicted states from evidence that a model supports useful action choices. The cited position paper uses an L0–L7 evidence ladder and discusses intervention fidelity, closed-loop validity, policy ranking, optimization lift, exploitability, and calibration. The benchmark survey reports 11 explicit world-model versus direct-policy comparisons among 160 surveyed benchmarks (7%). These reviews motivate the evaluation design; they are not reproduction results from this repository.
- **The latent-action paper** studies action discovery from in-the-wild video. It reports that sparse or noisy continuous latents cover a wider one-step prediction-capacity range than vector quantization, that actions can transfer across objects, and that transformations are mainly camera-relative. Notebook 12 tests a synthetic analogue with fixed image moments; its [run report](reproductions/latent-actions.md) does not validate the paper findings. The [reproduction matrix](REPRODUCTION_MATRIX.md) tracks the exact Figure 4 attempt as not run until code, checkpoint, data, and compute gates are verified.
- **LeWAM** ([arXiv:2610.12818](https://arxiv.org/abs/2610.12818)) jointly trains latent dynamics and action generation. Its official project page reports 98.7% ± 1.2 Push-T success for gradient planning, averaged over seeds 42, 0, and 1 with 50 episodes per seed. Its official repository provides released checkpoints, datasets, and a reproduction guide. This is a candidate local result, not a result from this project.
- **PiJEPA** ([arXiv:2603.25981](https://arxiv.org/abs/2603.25981)) uses a learned Octo policy to warm-start MPPI over a separate JEPA world model for language-conditioned visual navigation. Notebook 16 compares a hand-written controller prior with neutral-start CEM in a different simulator; it does not test PiJEPA's learned prior or MPPI result. The author repository is MIT licensed, but CAST data, Octo, the JEPA model, and GPU training/evaluation remain separate access and compute gates.
- **JEPA-WAM has multiple distinct papers**. This roadmap's main candidate refers to [Learning Vision-Language-Action Policies with Joint-Embedding World Modeling](https://arxiv.org/abs/2608.09381). Separate works include [Stage-Level Joint-Embedding Prediction for World-Action Models in Robot Manipulation](https://arxiv.org/abs/2608.10780) and [Connecting Generated Visual Instructions to World Action Models through JEPA Latent Representations](https://arxiv.org/abs/2609.20277). Treat each as a separate claim and artifact set.
- **V-JEPA Policy** ([arXiv:2609.37250](https://arxiv.org/abs/2609.37250), v2 dated 2026-10-10) combines frozen V-JEPA 2.1 features, a future-latent predictor, and a flow-matching action expert. Its reported evaluations use LIBERO, LIBERO-Plus, and RoboCasa. Its [first-party code](https://github.com/breez3young/VJEPA-Policy) is MIT licensed, but the repository still lists its trained checkpoints as planned releases. It is a distinct method from V-JEPA 2-AC and needs its own exact claim and artifact audit before a reproduction attempt.
- **RoboJEPA** ([arXiv:2610.10515](https://arxiv.org/abs/2610.10515), submitted 2026-10-07) reports second-order scaling of held-out DROID latent rollout error with compute, plus zero-shot goal-image planning results. Its [first-party repository](https://github.com/facebookresearch/robo_jepa) now provides code and checkpoints from 22M to 8B parameters. The repository license is CC BY-NC-SA 4.0; checkpoint evaluation also needs the V-JEPA 2.1 ViT-G/384 encoder. DROID holdout evaluation uses fixed clips and reports per-step latent L1 for steps 1–9. RoboCasa planning has four named tasks and released scripts, but the documented defaults are costly and some task settings differ from the paper. Treat RoboJEPA as a distinct new candidate; do not infer its scaling-law claim from one checkpoint or one local task.
- **Semigroup-JEPA** ([arXiv:2609.10464](https://arxiv.org/abs/2609.10464)) adds supplied gravity to a jointly trained latent model and measures 44-step prediction across held-out gravity values. Its square result favors SG-JEPA across position, velocity, and rotation, while the triangle's longest-horizon rotation result favors DINO-WM. The paper varies one scalar and uses a linear feature model to explain part of the error; neither implies general physical-law inference. The official [code](https://github.com/sg-jepa/sg-jepa/tree/1b7794b3b3a85e9f9746636553e0d5c30d249212) and [checkpoint manifest](https://github.com/sg-jepa/sg-jepa/blob/1b7794b3b3a85e9f9746636553e0d5c30d249212/CHECKPOINTS.md) are public. The current checkpoint bundle is incomplete for the four-method square comparison, and E:-hosted CUDA runtimes pass basic checks, but the full Semigroup comparison is unqualified and lacks three required checkpoints. See the [preflight](reproductions/semigroup-jepa-preflight.md).
- **JEPA-WAM** ([arXiv:2608.09381](https://arxiv.org/abs/2608.09381)) couples transition prediction with action generation. Its author README provides a released-checkpoint evaluation command for the LIBERO-Plus spatial suite, all seven categories, and one trial per task, and reports 79.2%. The pinned benchmark classification has 2,402 spatial task variants, so this is a large evaluation. The paper uses eight GPUs, batch 128, and 60,000 steps; the released recipe and checkpoint use batch 256 and 40,000 steps. This can re-check the released policy score, not reproduce the paper's training. The [preflight](reproductions/jepa-wam-libero-plus.md) records the model paths, terms, and host gates. Do not merge this paper with the separately named JEPA-WM physical-planning paper or the distinct LeWAM studies.
- **Notebook 16** records a local algorithmic analogue: neutral-start CEM reached 0/20 goals, controller-prior CEM and direct control each reached 20/20, and the direct controller used fewer model calls and reached goals sooner on average. These results show a task-specific failure mode for this learned model and planner; they do not establish the value of learned policy priors in JEPA systems. See the [run report](reproductions/action-video-planning.md).
- **Qantara** ([arXiv:2607.04978](https://arxiv.org/abs/2607.04978), v2 dated 2026-10-10) trains an approximately 21M-parameter JEPA for three inference paths from one checkpoint: goal-conditioned CEM planning, goal-blind behaviour-cloning action sampling, and video–inverse action recovery. It reports Push-T success rates of 90.1, 82.1, and 83.2, respectively, with the same three model seeds and five evaluation seeds. In the matched 10-epoch pipeline, Qantara scores 90.1 on Push-T versus 92.3 for the LeWM reproduction; its central result is that one checkpoint supports multiple paths with different latency and goal requirements. The paper reports simulation only at one scale and does not establish robot transfer. Its [official code](https://github.com/corl-team/qantara/tree/12429541011e8576eb4fe2bc589d059b0d29dd2e) and [MIT checkpoint release](https://huggingface.co/t-tech/qantara-checkpoints/tree/de5f7575c9db4a564382e4b2b681fa534dcb3b62) are public. Notebook 18 is a CPU analogy, not a paper evaluation. The Push-T data identity and local renderer remain unresolved. See [feature 019](../specs/019-qantara-multiparadigm/spec.md) and the [preflight](reproductions/qantara-preflight.md).
- **LeHami** ([arXiv:2610.15267](https://arxiv.org/abs/2610.15267)) adds Hamiltonian structure to an action-conditioned latent world model. Table 1 reports held-out K=0 angular-velocity MAE of 0.419 ± 0.045 rad/s for LeHami and 2.508 ± 0.002 rad/s for LeWM, using a 25-NN probe over three seeds. One local seed per model measured 0.456258 and 2.504686 rad/s. A separate seed-0 K=1-fitted, frozen 25-NN probe found lower LeHami error at K=1 and K=5, then lower LeWM error at the selected steps from K=10 onward. These single-seed curves do not reproduce the three-seed Figure 15 result or establish a planning benefit. Seeds 1 and 2 remain open for both models. See [Notebook 15](../notebooks/15_lehami_symplectic_dynamics.ipynb), [feature 013](../specs/013-lehami-actuated-reproduction/spec.md), the [local run record](reproductions/lehami-actuated-velocity.md), and the [tutorial code-cell check](evidence/lehami-symplectic-tutorial.md).
- **A separate preprint also named LeWAM** ([arXiv:2610.12407](https://arxiv.org/abs/2610.12407)) studies diffusion-steering-based MPC and reports that planning in action-policy noise space can improve closed-loop performance. [Notebook 20](../notebooks/20_policy_noise_planning.ipynb) is a CPU toy analogy, not the paper's method or benchmark. This research review did not find an official code or checkpoint link for that preprint. Keep it separate from arXiv:2610.12818.
- **Point-cloud JEPA planning** ([arXiv:2608.29434](https://arxiv.org/abs/2608.29434)) has a released [official repository](https://github.com/fafraob/point-lewm), versioned datasets, and checkpoints. Its October 2026 release says the checkpoints and paper results use v1; v2 changes sensor-view images and fixes Push-T scan replay. The v1 archive is 4,616,741,240 bytes with a recorded SHA-256 in the [reproduction matrix](REPRODUCTION_MATRIX.md). The bounded [Push-T feature](../specs/011-pointcloud-jepa-reproduction/spec.md) uses two released checkpoints and ten seeds × 50 episodes. Evaluation needs CUDA 12 and a 24 GB GPU. The host now has a CUDA runtime but only 12 GB VRAM, below the memory requirement.
- **JEPA-Anything** ([arXiv:2609.20800](https://arxiv.org/abs/2609.20800)) reports results across seven domains. Its [official repository](https://github.com/Gen-Verse/JEPA-Anything) describes a reusable core and synthetic structural example, and says the domain datasets and trained weights are not included. Treat the broad reported results as a research map until a claim has accessible artifacts and a bounded reproduction protocol.
- **GA-WM** ([arXiv:2609.03565](https://arxiv.org/abs/2609.03565)) combines inverse dynamics with physical-state alignment and reports goal-conditioned planning on four simulated tasks. Its [author-linked checkpoint page](https://huggingface.co/kikihuang/GA-WM) lists per-checkpoint success rates and says those values were not re-evaluated on upload. This review did not confirm a first-party code repository. Treat the method as a watch item until the implementation, fixed cases, and third-party terms are verified.
- **Hamiltonian JEPA** ([arXiv:2609.33497](https://arxiv.org/abs/2609.33497)) proposes a perceptual code with an inherited control state and port-inverse consistency. The paper reports results on four pixel-based control benchmarks, including 91.9% on OGB-Cube. This review did not find first-party code or checkpoints. Keep it separate from hierarchical H-JEPA and LeHami; no local result is available.
- **LeWAM for RoboTwin 2.0** ([arXiv:2609.27455](https://arxiv.org/abs/2609.27455)) reports 92.28% average success with 0.4B trainable parameters, joint latent prediction and action generation, AdaFuse, and DemoDPO. The [official README](https://github.com/XuejiFang/LeWAM) describes a 50-task, two-setting evaluation with 100 scenes per task and setting; this is 10,000 cases by calculation, under one seed. The [released checkpoint](https://huggingface.co/XuejiFang/LeWAM) is 4.13 GB and includes I-JEPA-Huge, whose model card states CC BY-NC 4.0. The code repository does not show a project license in the reviewed file list. Qualify a small fixed-case run first; do not equate it with the paper's full result.

## Acceptance rules for future lessons

Every new lesson must name its source paper and code, learning outcome, assumptions, data/model access needs, and local validation path. It must state which results are reproduced locally and which come from papers. A paper-reproduction attempt must select one reported claim before running and name all deviations from the paper setup. Map each claim to the evidence it needs: feature or prediction quality does not establish counterfactual fidelity; open-loop fidelity does not establish closed-loop task success; and a model's task success does not establish an advantage over a direct policy without a matched comparison. Planning claims must include the task, horizon, baseline, and feedback setting. Real-robot claims require direct robot evidence; a simulator result is not enough.
