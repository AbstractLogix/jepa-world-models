## Design and Interfaces

See [data-model.md](data-model.md) for the run and measurement records. There is no public software interface or external service contract. The notebook is the learner-facing interface.

The notebook uses Gymnasium for reset and step calls. A small local transition function supports batched CEM rollouts and is checked against the environment before evaluation. Use an explicit NumPy random generator per condition. Keep start seeds paired across planner modes.

The planner uses a fixed CEM budget of 64 candidate action sequences, 8 elites, and 2 iterations. Each candidate sequence has the condition's rollout horizon. The score is the minimum state distance to the active target over the predicted rollout, with a small action cost. Feedback MPC executes one action before observing again. Pure imagination plans from its predicted state and never reads later observations. Subgoal MPC uses a target five steps ahead on a reference path generated by the same-seed momentum rule, with the same model and planner. The momentum baseline pushes in the direction of current velocity, using positive force at zero velocity. State clearly that the reference path is a scripted teaching aid, not an expert demonstration.

## Risks and Mitigations

- The momentum-reference subgoal policy has a scripted reference path. Label its source and guidance advantage in every comparison; it is not an expert subgoal method.
- Exact dynamics can make open-loop and feedback look similar. Explain that feedback value depends on uncertainty or disturbances, which this deterministic example does not model.
- CEM results can vary with implementation and dependency versions. Fix seeds, display settings, preserve failures, and report the installed Gymnasium version.
- A short horizon can produce little score variation when all candidates remain far from the goal. Show the score/trajectory traces and do not assert that the local result matches the paper.
