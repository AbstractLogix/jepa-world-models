# Research: Planning Limits Lesson

## Decision 1: Teach the paper's planning factors with a small deterministic task

**Decision**: Use `MountainCarContinuous-v0` with its two-dimensional state and one-dimensional continuous action. Compare rollout horizons 5 and 20 and goals at 0.0, 0.25, and 0.45.

**Rationale**: This task is small, already supported by Gymnasium, and can run without a visual encoder, checkpoint, dataset, or robot. Its known transition supports an exact model check and makes planner behavior easy to inspect.

**Alternatives considered**: Reproduce Meta-World using the paper's models and data; this requires external artifacts, specialized setup, and much more compute. Reuse CartPole; the current lessons already use it, and it does not offer the same continuous position-goal illustration.

**Source**: [Gymnasium continuous MountainCar implementation](https://github.com/Farama-Foundation/Gymnasium/blob/main/gymnasium/envs/classic_control/continuous_mountain_car.py).

## Decision 2: Keep paper results as a separate evidence lane

**Decision**: Quote paper-reported values with their context, then report this notebook's values under a separate heading. Call the notebook an illustrative analogue, not a reproduction.

**Rationale**: The paper uses five learned visual predictors, sixteen Meta-World tasks, real-robot data analysis, and paired closed-loop episodes. This notebook uses one deterministic state-space task and a momentum-controller reference path. The evidence is not interchangeable.

**Paper context**: Version 1 of *The Planning Limits of Latent World Models* was submitted on 30 September 2026. It reports sixteen Meta-World tasks, twenty paired episodes per task, and a 5-step versus 30-step comparison. With a 5-step rollout, the reported completion success is 23% for pure imagination and 30% for feedback MPC; the 30-step MPC result is 52%; 5-step MPC with nearby expert subgoals reaches 76%. These values are from that paper's evaluation and are not tutorial measurements.

**Source**: [arXiv:2609.39235v1](https://arxiv.org/html/2609.39235v1), Sections 6.1–6.3 and Appendix B.3.

## Decision 3: Use exact dynamics and label the resulting boundary

**Decision**: Implement the published continuous MountainCar transition in a vectorized helper. Before evaluating planners, compare it with Gymnasium on fixed states and actions within absolute tolerance `1e-6`.

**Rationale**: The exact model isolates planning horizon and target choice from learned-model prediction error. It does not test representation quality, visual prediction, real robot control, or the paper's full evaluation.

**Source**: [Gymnasium continuous MountainCar implementation](https://github.com/Farama-Foundation/Gymnasium/blob/main/gymnasium/envs/classic_control/continuous_mountain_car.py).

## Decision 4: Use a bounded CEM planner and disclose the target rule

**Decision**: Use 64 action sequences, 8 elites, and 2 CEM iterations, with a 300-step episode limit. Score a candidate by its closest predicted state to the active target, with a small action penalty. For the teaching subgoal method, use a target five steps ahead on a same-seed trajectory from the momentum baseline.

**Rationale**: This keeps the comparison inspectable and uses the same model and candidate budget across planner modes. The reference trajectory makes the target local, similar to how the paper uses nearby targets from a demonstration. It is generated by the simple momentum rule, not an expert policy.

**Alternatives considered**: Use the paper's expert demonstration subgoals; that requires demonstrations and a different environment. Hand-code waypoints; a same-seed reference path better keeps start conditions paired and provides a concrete local target. Use one long action plan for every condition; that would not show the feedback MPC distinction.

## Open limits

- No author code or Meta-World assets are used by this lesson.
- Exact deterministic dynamics make it unsuitable for measuring the value of correcting model error with feedback.
- The momentum-reference path gives the subgoal planner a scripted target. It does not establish that a robot can generate useful subgoals without an expert or a scripted controller.
