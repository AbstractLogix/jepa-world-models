# Data Model: Action-Conditioned Video Planning

## Rendered transition

| Field | Meaning | Source | Use |
| --- | --- | --- | --- |
| `previous_frame` | RGB image before the last simulator transition | Pillow renderer | Input to frame-history feature extraction |
| `current_frame` | RGB image for the current simulator observation | Pillow renderer | Input to frame-history feature extraction |
| `action` | Scalar continuous control in `[-1, 1]` | Random collection, controller, or planner | Conditioning for the next-feature predictor |
| `next_frame` | RGB image after the action | Pillow renderer | Target for next-feature extraction |

## Visual feature

| Field | Meaning | Validation |
| --- | --- | --- |
| `position` | Car horizontal coordinate recovered from the red image region | Finite and inside the simulator's position range |
| `velocity` | Position difference between current and previous decoded frames | Finite and inside the simulator's velocity range, with tolerance for pixel quantization |
| `goal_position` | Target coordinate recovered from the green image region | Finite and equal across the episode |

The feature extractor receives only image arrays. The Gymnasium state is used to create frames and score realized results; it is not an input to the predictor or planner.

## Split and evaluation episode

| Record | Fields |
| --- | --- |
| Training transition | Training seed, episode step, visual feature, action, next visual feature |
| Intervention case | Held-out seed, visual start feature, candidate action, predicted next feature, simulator next feature |
| Evaluation episode | Seed, method, success, return, steps, planning seconds, predictor calls, terminal status |

Training, intervention, and closed-loop evaluation use distinct seed ranges. The same evaluation seed is reused for all three methods.

## Model and planner

- The predictor input is the current visual feature plus one action.
- The predictor target is the next position and velocity. Goal position is carried forward from the visual input.
- A planner candidate is a fixed-length vector of bounded actions.
- A planner result includes the first action, number of predictor calls, and elapsed search time.
- The prior-seeded CEM mean is generated by the direct visual momentum controller rolled forward through the same learned model.

## Evidence outputs

- One Markdown summary stores configuration, versions, aggregate results, and claim limits.
- One episode CSV stores every completed per-seed outcome. Missing or time-limited episodes are also represented with a status.
- One intervention CSV stores all 60 held-out state-action predictions and simulator outcomes.
- No generated image, video, dataset, checkpoint, or fitted model is retained.
