## Host and trust boundary

The RTX 5070 has 12 GB VRAM. A Python 3.10.12 environment on E: uses the pinned PyTorch 2.2.0+cu121 and NumPy 1.26.4 versions. PyTorch sees the GPU, but its matrix operation fails because the wheel lacks a kernel image for `sm_120`. A separate E: diagnostic environment uses PyTorch 2.7.0+cu128 and passes that matrix operation. The pinned source and evaluator import, and an isolated EGL context check passes in this environment. This differs from the author's tested Python 3.10.16, PyTorch 2.2.0, CUDA 12.1 setup; it does not confirm that a LIBERO task can render, a model can load, or the benchmark can run.

The WAM and LIBERO-Plus source checkouts, environments, pip cache, temporary files, model assets, extracted simulator assets, and evidence are under `E:\codex-research\jepa-wam\`. The project checkout remains in its current WSL folder. The policy checkpoint, base VLM, Qwen2.5-0.5B weights, V-JEPA checkpoint, LIBERO-Plus archive, and required JSON metadata are present and verified against pinned SHA-256 values or Hub Git blob IDs. The archive passed path checks and extracted successfully. With an E:-hosted Wand overlay, TensorFlow/TFDS dependencies, pinned `dlimp`, and the correct MagickWand paths, the pinned evaluator rendered one task and ran one policy action after ten no-op warm-up steps. It recorded 0/1 task success, which is pipeline evidence only. TensorFlow did not register a GPU; PyTorch loaded the model on the RTX 5070. No system packages or RLDS training data were added. See [storage and runtime evidence](../../docs/evidence/jepa-wam-storage-preflight.md) and the [diagnostic report](../../docs/reproductions/jepa-wam-libero-plus.md).

At the pinned JEPA-WAM source revision, the V-JEPA loader calls `torch.load` with `weights_only=False`. The pinned LIBERO-Plus source omits that argument when it loads NumPy initial states. PyTorch 2.7 defaults to `weights_only=True`, so the diagnostic set `TORCH_FORCE_NO_WEIGHTS_ONLY_LOAD=1` for that isolated run. This compatibility setting affects every call that omits `weights_only`; use it only with the pinned, trusted sources and verified assets. See [PyTorch's serialization environment-variable reference](https://docs.pytorch.org/docs/stable/notes/serialization.html#environment-variables).

## Decision

The one-task diagnostic passed with one policy action after ten no-op warm-up steps. The action ran on the pinned model and the LIBERO task rendered and stepped. The 0/1 outcome is not a paper score. The first task iteration took 92.46 seconds, which gives a naive estimate of about 61.7 hours for 2,402 tasks; one task is not a reliable runtime sample. Keep the full spatial suite pending and agree on a separate scope and runtime estimate before starting it. Do not download training data, other suites, or the full Hugging Face repository.
